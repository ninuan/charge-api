# Charge · 交互原型

原型入口：`http://127.0.0.1:3000/prototype/`（随前端开发服务运行）。

在仓库根目录运行：

```sh
pnpm --dir frontend dev --hostname 127.0.0.1 --port 3000
```

右上角「示例数据 · 预览设置」可切换普通用户 / 管理员 / 未登录，预览加载、空、失败、断网、凭据失效、断电和限额状态；也可以模拟空闲通知、离线恢复、新增设备首次读取。修改密码、扫码和通知发送均为明确标注的模拟流程。

这是一次从业务契约出发的信息架构重建，不沿用已删除的旧原型。正式页面及其已有修改不变；所有新增代码位于 `frontend/app/prototype/`。不连接业务 API，不读写真实账户、Cookie、设备或通知。示例数据与操作保存在当前浏览器的独立原型存储中，可以通过「预览设置」重置。

## 从用户的问题组织界面

| 用户要知道 / 要做什么 | 页面与信息优先级 | 闭环 |
| --- | --- | --- |
| 常去的地方现在能充吗？ | 常用桩列表：名称、空闲口、连接状态、快照时间 | 搜索 / 筛选 → 选桩 → 选口 → 返回列表 |
| 具体哪个口可用？ | 桩详情：空闲数量 → 编号与状态 → 使用时长 / 剩余时间 | 就地选口 → 当前情况 / 单口历史 |
| 现在没空位，能提醒我吗？ | 提醒属于整桩；入口在桩详情，不放在单口上 | 选择 1 / 2 / 4 小时或到断电前 → 创建 → 调整 / 取消 → 通知 → 回到桩 |
| 平时什么时候比较空？ | 同一桩详情的历史页，24 小时 / 7 天 / 30 天 | 整桩与单口切换；展示观察覆盖，不把未知当空闲，不预测空位 |
| 这条消息需要我做什么？ | 通知按未读、待处理、已解决组织，消息连接业务对象 | 标为已读 ≠ 问题已解决；凭据问题跳到账户连接，设备问题跳回桩 |
| 为什么不能刷新 / 收不到提醒？ | 账户：连接状态、通知渠道与偏好、安全、外观 | 扫码 / 手动凭据、测试发送 / 查询结果、免打扰、改密、退出其他会话 |
| 管理员今天要处理什么？ | 独立管理工作区：异常 → 用户 → 系统运行与策略 | 异常定位用户 → 检查凭据 / 刷新 / 限额 → 确认 / 解决；审计记录变更 |

## 业务边界

- 充电桩包含充电口。常用桩不是充电站地图、订单、费用或远程启动充电的平台。
- 桩信息支持添加、名称 / 位置编辑、排序、移除；刷新是整批请求。单桩入口不伪装成不存在的独立刷新 API。
- 提醒是当前版本的临时整桩规则。发现空闲后通知一次并结束；旧周期规则仅只读，不提供新建周期规则或单口提醒。
- 离线 / 失效 / 刷新失败保留最近快照并标记过期；不会用旧空闲状态声称当前可用。
- 站内通知为主记录；微信渠道受理或处理成功，不等于手机送达或用户已读。
- 管理员与普通用户是分开的角色；只有「原型预览设置」可以切换示例角色。
- 扫码、登录和密码流程只模拟状态，不索取真实密码、Cookie 或微信授权。新增设备默认没有已观察的端口数据。

## 实现与验证

使用项目已安装的 [shadcn/ui / Base UI](https://ui.shadcn.com/docs/components/base/dialog) Button、Dialog、Tabs、Input、Switch、Skeleton，以及 Lucide 图标；样式与业务状态在原型命名空间中隔离。使用连续分区、主从详情、可访问的模态窗和轻量状态过渡。没有为了装饰加入第三方动画包。

浅 / 深主题；桌面主从并列、窄屏列表 / 详情分步；键盘可操作、焦点恢复、Escape 关闭、系统减少动态效果；浏览器历史与直接定位；加载、空、失败、断网、凭据失效、断电窗口、限额等可切换预览。

验证结果和复测命令见 [VERIFICATION.md](VERIFICATION.md)。
