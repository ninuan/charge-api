## 1. 实现结果

### 添加充电桩

- 共用添加组件的顶部入口与空列表入口都会先查询平台绑定状态。
- `scanEnabled=true` 且未绑定、明确过期或未知账号状态时，直接展示扫码步骤，自动生成一次二维码；已绑定且无明确异常时直接进入填写。
- 未配置扫码或旧接口缺少能力字段时，保留填写与手动 Cookie 设置。网络失败显示重新检查，不能误判为未绑定。
- `YYB_BINDING_REQUIRED` / `YYB_RESCAN_REQUIRED` 在表单内显示错误与扫码入口；其他添加错误保留表单，不引导重新绑定。
- 使用一个弹窗切换步骤，草稿由父组件保存。确认绑定后展示成功，由用户点击“继续添加充电桩”返回并聚焦桩号；不会自动提交。
- 返回填写、关闭再打开不会清空草稿；添加成功后才清空。凭据不写入浏览器持久存储。

### 扫码与确认

- 添加入口和账户设置共用 `YybBindingFlow`。
- 仅当前二维码收到 `authorized` 或 `confirmed` 后启用“确认绑定”；扫码、离线、未知、过期、取消或请求失败时不可确认。
- 持续显示微信授权与本站确认的区别，删除自动保存和永久保持有效的承诺。
- 确认成功区分 `not_needed`、`synced`、`failed`。没有设备时无需同步；绑定已保存但同步失败时显示警示说明，指向账户设置中的同步操作。
- 串行约 3 秒检测；连续三次失败暂停，提供手动重试。授权后停止自动检测；手动与自动检测不会重叠。
- 关闭、换码和断网会取消请求并使旧响应失效。恢复连接需要重新检查；账户重新绑定不会被旧 `bound=true` 阻止。
- 确认超时后查询同一二维码会话，不依赖旧账户的绑定状态推断成功。

### 后端与版本契约

- 二维码创建时记录本站用户归属；轮询与确认均校验归属和有效期，确认时再次校验上游授权状态。
- 同一二维码确认期间拒绝重复确认；已完成的重复请求返回同一结果。轮询返回 `confirming` 或带会话关联绑定结果的 `saved`。
- 绑定保存后的设备读取/凭据同步失败仍返回 `bound=true`，通过 `syncState` 表达失败，不返回含糊的绑定失败。
- 会话与确认结果在当前后端进程中保存 30 分钟，最多 4096 个；创建时清理过期会话，不覆盖同名有效会话。重启后未完成二维码需重新生成，不影响持久化绑定。
- 扫码服务实际长轮询最长约 35 秒；客户端为轮询单独使用 40 秒超时，前端为 45 秒，普通后端远端接口仍为 10 秒。
- 版本常量、前端 package、OpenAPI、类型生成引用、README 与发布说明更新为 1.5.3。pnpm 锁文件不记录根包版本，依赖未变，无需虚构 lock 变更。
- 原有凭据恢复修复保留，不将本版引导功能描述为解决长期凭据过期根因。

## 3. 真实服务契约核对与待人工验证

已读取本机 `yyb_go/internal/qr/qr.go` 的实际实现：等待/扫码分别为 `pending` / `scanned`，微信授权成功为 `authorized`，已生成登录材料为 `confirmed`，取消/过期/未知有独立状态；确认实现要求已有授权码。已据此实现状态门槛与客户端契约测试。

本次未调用真实微信授权，也未取得用户授权操作部署账户。以下项目仍需在部署环境用测试用户验证：

1. **首次绑定**：未绑定用户点击添加，二维码自动出现；手机仅扫码时按钮禁用；微信确认授权后按钮启用且提示持续可见。
2. **本站确认**：点击确认绑定，看到微信已绑定；点击继续添加，填写真实桩号，添加成功并定位新桩。未点击确认时，不应显示绑定完成。
3. **已有账户重绑**：已有绑定不先解除，重新扫码授权后可确认；失败保留原绑定。检查扫码状态与部署 sidecar 的实际返回一致。
4. **同步失败反馈**：使用可控测试环境模拟 Mocele 不可用，确认页面仍说明绑定已保存，并提示到账户设置重试同步；恢复服务后验证同步入口。
5. **真实手机与键盘**：在实际手机检查可滚动区域、系统键盘及微信扫码指引；桌面用 Tab 逐项导航，并验证浏览器/辅助技术的焦点与状态播报。
6. **部署切换**：前后端同时更新；重启前未完成二维码重新生成；已有绑定与设备仍存在。若使用多后端实例，需要会话固定到同一实例。

这些项目未勾选为完成，也未把生产人工验收当作自动化结果。复测时只记录状态、错误码和结果，避免记录完整 Cookie、OpenID、ref、code 或服务密钥。

## 5. 2026-09-14 合并前代码审查

审查范围包括 1.5.3 新增扫码会话、共用扫码内容、添加入口、手动凭据、错误码、版本契约及同批未提交的凭据状态修复。以下问题已修复：

1. **P1：绑定变更缺少账户级并发保护。** 不同二维码可以同时确认，解绑也能在确认期间成功，较慢的旧请求随后可能重新保存绑定。新增账户级操作互斥，确认、显式同步与解绑冲突时返回 `409 YYB_BINDING_BUSY`；取得操作权限后重新检查会话有效性。新的确认保存后，使该用户其余二维码（含旧确认结果）失效。
2. **P1：进行中的自动凭据恢复可能覆盖新绑定或恢复已解绑账号。** 在运行时用账户级锁串行化凭据恢复和绑定替换/删除，覆盖添加、刷新触发的恢复路径，不仅保护手动同步接口。锁顺序为 credentialMu → refreshMu / runtime.mu，检查过调用路径，无反向获取。
3. **P2：绑定成功页的“返回填写”绕开完成事件。** 旧快捷入口只切换页面，不清除“需要绑定”限制，可能让用户重复扫码。现在确认处理中禁用返回，保存成功后隐藏该入口，只能通过“继续添加充电桩”恢复已解锁的原表单。

验证证据：新增并发 API 用例在修复前复现不同二维码同时确认返回 200、解绑返回 204；修复后均返回冲突，旧会话失效。新增运行时测试覆盖恢复期间重绑/解绑，新绑定不会被旧恢复覆盖，解绑后不恢复旧绑定。新增前端测试及浏览器断言覆盖确认中返回禁用、成功后快捷返回消失。

合并边界：仅执行本地主分支合并，不自动推送或部署。已有 `.gitignore` 中的 `artifacts/` 本地排除项保持原样，不纳入本次功能提交。真实服务扫码与多实例限制继续按第 3 节验收。
