# 凭据恢复诊断与扫码会话修复

## 范围与依据

- 独立分支：`codex/yyb-recovery-and-qr-session`，验证通过后合并本地主分支。
- 9 月 14 日日志显示获取临时凭据返回 409，随后账号刷新被判为 expired。扫码服务将多种恢复错误归为 expired，现有日志无法确定具体原因，不能认定刷新令牌已过期。
- 本地扫码服务源码 `internal/qr/qr.go` 的 PollResult 仅输出 status 和可选 errcode，不输出 session_id；Charge 原样返回空会话 ID，前端因此拒绝正常响应。这是接口适配缺陷，提前轮询并不代表二维码已被消费。

## 修改计划

1. 在 Charge 的 YYB 客户端适配轮询响应：没有 session_id 时，使用本次请求已确定的会话 ID；显式返回其他 ID 时拒绝响应。保留用户归属校验、前端会话一致性校验、取消旧请求与串行轮询。
2. 保持交互流程：生成二维码后自动检测，等待手机确认；只有 authorized/confirmed 才可确认绑定。手动检查与自动检测不能并发，延迟确认后仍可继续绑定。
3. 管理端恢复记录展示账号刷新 expired/unknown 事件，完整呈现失败链路。
4. 提供独立扫码服务的可审查诊断补丁与部署说明。只记录固定阶段、错误分类和数字状态码，不输出令牌、身份信息或原始响应；不改变令牌恢复策略。Charge 合并并不等于扫码服务已部署补丁。

## 验证方案

- YYB 客户端契约测试覆盖真实无 ID 响应、显式匹配 ID、不同 ID 拒绝；覆盖 pending/scanned/authorized/confirmed 及结束状态，兼容包装响应与直接 JSON。
- 现有 API 测试验证扫码归属、确认前置状态、重复确认与绑定变更互斥。
- 浏览器验证二维码生成后自动检测、延迟手机确认、再次手动检查、确认绑定完成；保留旧会话隔离测试。
- 管理端测试验证两种刷新失败记录均可见。
- 扫码服务补丁在隔离副本上应用并运行全部 Go 测试；检查敏感字段不会出现在诊断中。
- 运行项目 make check、相关 Go race 测试和实际浏览器用例；检查差异后提交并合并本地 main。

部署 Charge 可修复扫码会话适配并补全管理端失败链路；想在下次凭据同步失败时看到具体阶段，还需要单独部署 [扫码服务诊断补丁](../../scripts/patches/yyb-recovery-diagnostics.md)。本次不包含服务器部署和远端推送。
